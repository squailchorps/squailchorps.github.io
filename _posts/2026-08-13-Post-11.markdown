## Methods:

The point of this project was to try and learn a new language, program, and style of coding to push myself into a more well-rounded coder. I would utilize unity tutorials to get the start of how to use Unity, then from there look at documentation, unity forums, and other tutorials for things I needed. Looking back, tutorials on how to utilize C# better would have likely benefit me greatly, but hindsight is 20/20. Some of the tutorials I used were for how to change the color of a button using C#, a general Unity tutorial by GMTK (Game Makers Tool Kit), and Unity forums about specific issues (how to change the color of a button, how to change text with C# code, how to link objects together, etc.). The greatest piece of help was the GMTK video on Unity, as it was based on a mistake style learning (“Try something, break it, see how to fix it”) which was helpful in breaking part of my notion of the code needing to be right the first time or I am a “bad coder”. Lastly, since I have spent the past year in only theory territory, I played some coding games and looked through a lot of my own code to remember what I have done in the past and get myself acclimated to coding again. One of the games I played is “The Farmer Was Replaced”, which is a python like language game to teach you the basic ideas of coding. It was very helpful in reminding me how to code and what the thinking is like when we aren’t talking about the math side of CS.  
Over all, these above items were used to help get my pushed into creating my own things. I wanted to try and do something I did not know how to do to push me outside of my comfort zone. I have never made a game, never opened Unity, and never coded in C#. These things were uncomfortable, but going through the process of seeing something that is intimidating and learning how to do it over these 13 weeks was to show me I can learn to do things that I don’t know.
